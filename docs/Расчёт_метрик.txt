1. Метрики операционной эффективности
	1. Time Reduction % (Снижение времени андеррайтинга на одного клиента)
Система автоматического вычисления прогноза снижает время, затраченное на автоматическое выполнение прогноза, по сравнению с ручным способом вычисления стоимости страхования.
Time Reduction % = (Базовое время - Новое время) / Базовое время × 100%
Базовые расходы (в среднем) = 60 мин
Новые расходы (в среднем) = 10 мин
Time Reduction % = 83% снижения затра по времени
	2. Cost Saved per Month (экономия в рублях за месяц)
Рассчитаем для средней компании и средней зарплате аналитика 100 000 руб/мес. 
Cost Saved per Month = (Базовое время - Новое время) × Часовая ставка аналитика × Количество прогнозов
Cost Saved per Month = (50 мин/60)час × 650 руб/час × 18000 прогнозов/мес = 9 750 000 руб/мес
	3. OPEX (Operating Expenses) - текущие операционные расходы на эксплуатацию ИИ-системы
Стоимость затрат на поддержания инфраструктуры на 1 месяц.
Рассчитаем стоимость для средней страховой компании: 15 офисов, 300 сотрудников из них 60 - страховых аналитиков (одновременно в день работает 30 аналитиков). В среднем в день аналитик обрабатывает 20 случаев => с учётом повторных отправок и правок возьмём с запасом 40 случаев => 1200 случаев на компанию. Тогда в месяц получается требуется обрабатывать 36000 случаев.
Средняя загруженность: 2-3 запроса в минуту
Число серверов с учётом георезервирования для надёжности: 2 шт. Требуемые параметры серверов:
- CPU 16 ядер
- RAM 32 GB
- СХД 2 TB (с учётом хранения исторических данных 3 года + хранение данных модели)

Стоимость аренды двух серверов в облаке с данными параметрами (Yandex Cloud) - 55 000 руб/мес.
Стоимость аренды PostgreSQL в облаке (Yandex Cloud) - 40 000 руб/мес.
Интеграция с dadata: подсказки 10000 запросов в день - бесплатно; стандартизация - 7200 руб/мес.
Техническая поддержка (обновление, восстановление после сбоев, поддержка) - 50 000 руб/мес.
OPEX = 152 200 руб/мес.
Данная конфигурация сервера является минимально необходимой и позволяет обрабатывать до 500 000 запросов в месяц без существенной деградации производительности. Это означает возможность использования и для более крупной компании. 
	3. Cost per Inference
Систему необходимо развернуть на сервере, чтобы удалённо выполнять запросы.
Cost per Inference = (Затраты на инфраструктуру модели за период) / (Количество инференсов за период)
Затраты на инфраструктуру модели за период = 147 200 руб/мес.
Количество инференсов за период = 36 000 в мес
Cost per Inference = 4.1 руб.
	4. Return on Investment (ROI)
Показывает окупаемость за месяц
ROI (месячный) = (Cost Saved - OPEX) / OPEX × 100%
ROI (месячный) = 6306 %

2. Архитектурные метрики надежности
	1. Latency (время отклика) 
Время ответа системы на запрос расчёта предсказания прогноза.
Latency P95 = 57,237 мсек. (10000 запросов на локальный сервер)
Для удалённого сервера Latency P95 ~= 200 мсек.
	2. Throughput (Пропускная способность)
Сколько операций система обрабатывает в единицу времени.
Throughput = 14 прогнозов/сек.
	3. API Error Rate (частота ошибок API)
Отношение числа неспешных запросов к числу успешных.
API Error Rate = 0,03 %
	4. Initial Load Time (время начальной загрузки)
Initial Load Time P95 = 2,23 сек.

3. Метрики Tesseract OCR
	1. Среднее время распознавания анкеты OCR
Time OCR = 3,51 сек
	2. Accuracy 
Точность для печатных документов (идеальные условия). Процент правильно распознанных символов или слов от их общего количества в эталонном тексте.
Accuracy = 95% - 98%
	3. CER (Character Error Rate)
Частота ошибок на уровне отдельных символов. Считает количество вставленных, удаленных или замененных символов.
CER = 1.5% - 2.5% - для фото документов
